## FB-128: Detected spec drift doesn't reach the user — fast-path masking, a fast exit ahead of reconciliation, and no "absorb" path

**Status:** new — (a) and (b) verified defects, (c) verified gap · **Source:** cluster 1; 11 exports, 3 projects (oemmat 08-03-1349, 08-04-0420, 08-05-1641; tinder-streamliner-cc 05-25-0312; styler 06-21, 09-21, 09-24-2256, 09-28, 09-30, 10-01-1237, 10-01-1440). Extends FB-106 (v5.4.0), which covered new sections only.
(a) `dashboard-render.py:185,381` stamps the *current* spec hash into META, and `work.md:207` skips Steps 1a/1b when it matches. After any Tier-1 regen (e.g. at pause) that follows an `/iterate` edit to an existing section, Step 1b stops comparing task fingerprints, and `pending_decomposition[]` (`:217-224`) covers new `## ` sections only.
(b) Step 1d's fast exit (`work.md:263-302`) returns before Drift Reconciliation (`:304-306`), so drift found in 1b is never shown when no Claude-actionable task remains, even when reconciling it would unblock work.
(c) When drift does surface, `drift-reconciliation.md:270-290` offers only Apply (resets every Finished task to Pending), Review or Skip. Nothing keeps verification for annotation-only edits or a spec that caught up to shipped code: styler chose that ad hoc three times for one section, and one session hand-updated 304 fingerprints.
**Fix sketch:** stamp a task-provenance fingerprint in META, or have `/iterate` write a `pending_drift_reconciliation[]` marker (the FB-106 pattern); run reconciliation before Step 1d exits; add a per-section `[K] Keep verification` that refreshes fingerprints and notes it (it relaxes the `:290` invariant, so only on the user's choice). Design (a) and (c) together, because fixing (a) makes (c) fire on every annotation-only edit.

## FB-129: Agent-recorded decisions land `approved` before verification and never reach the user for ratification

**Status:** new — verified · **Source:** cluster 2; 9 exports, 3 projects (PW 09-08-2329, 09-11-0757, 09-15-1510, 09-19-0005, 09-24-1758; oemmat 05-24-1930, 07-22-2017, 07-23-0130; styler 05-27-0045). FB-052 (archived) created the field; its approval semantics were never revisited.

## FB-130: No defined path for a small fix after a verify pass

**Status:** new · **Source:** cluster 3; 5 exports, 2 projects (PW 09-27-1040, 10-02-0820; styler 09-28-1923, 10-01-1237, 10-01-1440). Four are on 5.7.4, after FB-119 made verify-agent an invariant (v5.6.0). No recurrence found in `processed/`.
